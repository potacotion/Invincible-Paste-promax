> 一个旨在绕过各种粘贴限制、并实现跨虚拟机（VM）文本传递的开源工具。
> A Windows typing-simulation tool that bypasses paste restrictions and supports host-to-VM text transfer through an Interception-driver based advanced mode.

---

## 📖 项目简介

在许多特定的软件环境（如金融终端、远程桌面、虚拟机、考试系统等）中，常规的 `Ctrl+V` 粘贴功能往往会被禁用或限制。此外，在去虚拟化的虚拟机（Hardened VM）中，由于禁用了虚拟机工具（如 VMware Tools 或 VirtualBox Guest Additions），物理机与虚拟机之间的剪贴板共享往往失效。

**无敌粘贴大法 ProMax** 正是为了解决这些痛点而生：它通过模拟底层键盘输入的方式，将文本逐字“敲”入目标窗口，从而绕过几乎所有的粘贴限制；并内置了一套基于特征码协议 + 虚拟机接收端的跨 VM 文本传输方案。

> 说明：本仓库与 `potacotion/invincible-paste-typing`（重写版）是两个**相互独立**的项目，代码、打包产物均不共享；本仓库包含 Interception 驱动高级模式（虚拟机穿透）。

---

## ✨ 核心特性

- 🛡️ **绕过粘贴限制**：模拟键盘按键（SendInput / 驱动注入）而非剪贴板 API，目标软件会将其视为人工输入。
- 🌐 **跨虚拟机（VM）穿透**：配合虚拟机内的接收端，无需安装 VMTools 即可实现物理机 → 虚拟机的文本传递。
- ⚙️ **底层驱动模式（高级模式）**：集成 `Interception` 驱动，将文本编码为 HEX 特征码注入按键流，兼容性更强。
- 🔄 **传输中断自恢复**：中途停止也会补发结束符；接收端 5 秒空闲超时自动退出捕获，重传时自动重同步并清理残留字符。
- 📋 **双输入模式**：支持读取剪贴板内容，或在软件内手动输入/粘贴待发送文本。
- ⌨️ **自定义打字参数**：支持打字间隔、随机间隔（模拟真人）、触发延时。
- 🎯 **全局热键**：默认 `F8` 开始 / `F9` 停止，可自定义；注册失败自动回滚，不会把原有热键弄丢。
- 💾 **配置自动保存**：配置固定保存在程序所在目录，原子写入，非法配置自动回退，损坏文件自动备份。
- 🈶 **中文与 Unicode 支持**：发送端逐字符注入，接收端按字符能力自动选择 Unicode 注入方式，不丢字。

## 🛠️ 安装与要求

### 环境要求
- Windows 10/11
- Python 3.8+（源码运行）
- 高级模式需要管理员权限安装 Interception 驱动并重启系统

### 源码运行
```bash
pip install -r requirements.txt
python promax_app.py
```

### 打包（PyInstaller）
```bash
pyinstaller --noconfirm "无敌粘贴大法promax.spec"
pyinstaller --noconfirm "虚拟机接收端_输入法模式.spec"
```
产物位于 `dist/`：
- `无敌粘贴大法promax.exe`：物理机发送端（`uac_admin=True`，运行时会请求管理员权限）
- `虚拟机接收端_输入法模式.exe`：虚拟机接收端

### 依赖库说明
- `PyQt5`：图形界面
- `keyboard` / `pynput`：常规模式按键模拟与全局热键
- `pyperclip`：剪贴板读取
- `pywin32`：前台窗口进程检测
- `interception-python`：高级模式的底层驱动调用（`pip install interception-python`）

## 🚀 使用指南

### 1. 常规模式（模拟打字）
适用于大多数禁用粘贴的常规软件（网页表单、客户端等）。

1. 运行 `promax_app.py`（或打包后的 exe）。
2. 选择“剪贴板模式”或“输入模式”，并确认待发送文本。
3. 按需设置“打字间隔”（建议配合“随机间隔”模拟真人）。
4. 点击“应用热键”（默认 `F8`）。
5. 切换到目标输入框，按 **F8** 开始输入；按 **F9** 随时中断。

### 2. 高级模式（虚拟机穿透）
适用于去虚拟化 / 未安装 VMTools / 常规模式无效的环境。

#### 第一步：安装 Interception 驱动
1. 主界面点击“下载并安装驱动”（自动使用内置的 `Interception_Installer`，无内置文件时自动下载）。
2. 在 UAC 弹窗中确认，等待安装器输出 `Successfully installed`。
3. **安装完成后必须重启计算机**，驱动才会生效。
4. 重启后主界面“驱动状态”应显示“Interception 驱动已就绪”。

#### 第二步：部署虚拟机接收端
1. 把 `虚拟机接收端_输入法模式.exe` 拷贝到虚拟机内运行（会请求管理员权限）。
2. 接收端启动时会自动注册开机自启（见下方“取消自启动”）。
3. 接收端常驻后台监听特征码序列，不需要界面。

#### 第三步：开始传输
1. 在物理机上勾选“启用高级输入模式”。
2. 在虚拟机窗口内点击激活目标输入框。
3. 按 **F8**：发送端将文本按 UTF-8 编码为 HEX，用特征码包裹后注入按键流。
4. 接收端捕获特征码 → 删除屏幕上的过渡字符 → 还原文本并逐字输入。

#### 中断与异常处理
- 传输中按 `F9` 停止：发送端仍会补发结束符，接收端删除未完成的过渡字符，屏幕上不会留下残留内容。
- 发送端异常退出：接收端空闲超过 5 秒自动退出捕获模式，不会“卡死”污染下一次传输。
- 上一次传输中断后又发起新传输：接收端识别到新的起始特征码后会重置本次捕获并清理残留。

## ⚙️ 详细配置项

| 配置项 | 说明 | 取值范围 |
| :--- | :--- | :--- |
| **输入来源** | 剪贴板模式 / 输入模式 | `clipboard` / `input` |
| **打字间隔** | 每个字符之间的等待时间（秒） | 0.0 ~ 1.0 |
| **随机间隔** | 在设定间隔基础上 ±50% 波动，模拟人类节奏 | 开 / 关 |
| **触发延时** | 按下热键后等待多久开始输入，便于切换窗口 | 0.0 ~ 60.0 |
| **触发键** | 开始输入的全局热键 | 默认 `F8` |
| **停止键** | 中断输入的全局热键 | 默认 `F9` |
| **高级模式** | 使用 Interception 驱动 + HEX 特征码协议 | 开 / 关 |

> 热键说明：触发/停止键会被全局拦截（`suppress`），以避免热键被发送到目标窗口。不建议使用单字符热键，否则该字符在系统任何地方的输入都会被吞掉；建议使用 `F` 系列或组合键（如 `Ctrl+Alt+P`）。

## 🗂️ 配置文件与数据

- **配置文件**：`config.json`，固定保存在程序所在目录（打包后为 exe 同目录，源码运行为脚本同目录），不随启动目录变化。
- **写入方式**：先写临时文件再原子替换（`os.replace`），避免写一半损坏；关窗时会再保存一次。
- **容错**：非法/超范围配置项自动回退默认值并在日志区提示；无法解析的配置文件会备份为 `config.json.bak` 后使用默认配置。
- **接收端自启动**：写入注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `ProMaxPasteReceiver`。取消方法（在虚拟机内执行）：

```cmd
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v ProMaxPasteReceiver /f
```
也可以在“任务管理器 → 启动应用”中禁用。

## ❓ 常见问题

- **按热键没反应**：确认日志区出现“已注册触发热键”；若提示注册失败，检查热键格式（如 `F8`、`Ctrl+Alt+P`），或是否与别的软件冲突。
- **目标窗口是本程序自身**：程序检测到前台窗口为自身时会自动停止，避免自我循环。
- **驱动状态显示“库已安装，但驱动未安装或未生效”**：运行安装器后必须重启系统；仅 `pip install interception-python` 不会安装驱动。
- **接收端在虚拟机里没反应**：确认接收端进程在运行，且虚拟机窗口内的输入框已激活；首次运行接收端需要管理员权限。
- **传输后残留 `]]u[[` / HEX 字符**：属于异常中断场景，接收端空闲 5 秒会自动退出；重新传输一次即可自动清理并重同步。
